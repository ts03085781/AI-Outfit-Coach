# 分析結果頁顯示照片設計

## 目的

讓使用者在閱讀穿搭分析時，能直接對照本次被分析的照片。

## 範圍

- 僅在一般成功分析結果顯示照片。
- 照片位置：進度條下方的結果卡內，`你的穿搭建議` 標題下方、摘要前。
- 全寬固定容器，高度約 `18rem`；使用 `object-fit: contain` 保留完整照片比例。
- `retake_required` 結果不顯示照片。

## 資料與隱私

- 使用已壓縮且已送交分析的圖片 Blob。
- 成功分析後保留 Blob 於前端 React state，供結果頁使用。
- 結果元件以 `URL.createObjectURL` 建立僅限本機的預覽網址，卸載或照片變更時以 `URL.revokeObjectURL` 釋放。
- 不新增圖片上傳、資料庫、localStorage、sessionStorage 或 URL 參數。
- 重新選照、回第一步、分析要求重拍、元件卸載與頁面重新整理後，不保留照片。

## 元件與資料流

1. `useOutfitFlow` 在成功分析後不清除 `image`；既有離開流程維持清除。
2. `OutfitFlowPage` 將 `flow.image` 傳入 `ResultStep`。
3. `ResultStep` 僅在非重拍結果且有圖片時，於標題下渲染具描述性替代文字的圖片。
4. 結果圖片樣式獨立於照片選擇頁的預覽樣式，避免影響上傳步驟。

## 錯誤與邊界

- 沒有圖片時仍正常顯示既有文字結果，不渲染空白區塊。
- 分析暫時失敗時，既有重試行為與照片保留行為不變。
- 使用者選新照片時先清空舊照片，避免錯誤對照。

## 驗證

- 單元測試：成功結果會顯示本機圖片；重拍結果不顯示；離開結果時 object URL 被釋放。
- E2E：成功流程可見結果圖片；320、390、430px 寬度無水平捲動。
- 執行 `pnpm test`、`pnpm typecheck`、`pnpm lint`；此為使用者流程變更，另執行 `pnpm test:e2e`。
