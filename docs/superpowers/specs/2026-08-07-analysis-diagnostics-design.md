# 分析失敗診斷設計

## 目標

將穿搭分析失敗分為可處理的安全類別，讓使用者取得對應的下一步，同時讓伺服器保留足以追查的非敏感診斷資訊。

## 範圍

分析流程會區分下列結果：模型拒絕、額度或權限問題、模型回覆格式失敗、逾時，以及其他暫時性服務問題。既有成功、重拍與圖片驗證行為不變。

## 資料流程

OpenAI adapter 會將供應商 HTTP 狀態、拒絕輸出與結構化輸出驗證失敗轉換成具名錯誤。Analyze route 將其轉換為穩定 API error code；前端依該 code 顯示固定中文訊息。未知錯誤仍採 fail-closed 的服務暫時不可用結果。

## 隱私與安全

伺服器診斷只記錄 error code、供應商 HTTP status、供應商 request ID 與處理階段。不記錄 API key、圖片、base64、使用者輸入、模型完整回覆或原始例外訊息。前端不接收供應商 request ID 或原始錯誤。

## 使用者訊息

每個 error code 對應一則簡短繁體中文訊息與相同的重試操作。額度／權限訊息會提示檢查 OpenAI Platform 專案設定；格式失敗訊息會提示稍後重試；拒絕訊息會提示更換清楚、合適的穿搭照；逾時訊息會提示再次嘗試。

## 驗收與測試

單元測試需證明 OpenAI adapter 能分類各類供應商失敗，route 能回傳正確 error code，且前端能顯示對應訊息。另需驗證診斷輸出不含圖片或 API key。最後以本機 API 的無真人測試圖片完成 smoke test。
